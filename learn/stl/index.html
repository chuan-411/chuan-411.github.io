竞赛中的 STL

把「手写容器」的时间省下来：用对容器，代码短一半，风险也少一半。 · vector 均摊 O(1)；set/map 每次 O(log n)；priority_queue O(log n)

一句话理解

STL 是别人替你写好的、经过反复验证的数据结构与算法。竞赛里它最大的价值不是「高级」，而是让你把精力放在建模上，而不是放在链表指针有没有写错上。

核心思想

先按「你要什么能力」选容器：

需求选择单次复杂度
随机访问、尾部增删vector均摊 O(1)
变长字符串string均摊 O(1)
头部也要增删dequeO(1)
有序、去重、找前驱后继set / mapO(log n)
有序但允许重复multiset / multimapO(log n)
只要快速按值查找，不要求有序unordered_set / unordered_map平均 O(1)
后进先出 / 先进先出stack / queueO(1)
每次取最大（小）priority_queueO(log n)

vector 是默认选择：连续内存、缓存友好、常数小。只有在需要「中间频繁插入」时才考虑 list（但它的遍历常数很大，实战中常被 vector 打败）。set/map 是红黑树，能顺序遍历、能 lower_bound；unordered_* 是哈希表，平均更快但能被出题人构造数据卡成 O(n)，n 较大且时限紧时优先用 map。

<algorithm> 里必须熟记的几件套：

  • sort / stable_sort：O(n log n)，比较器要严格弱序。
  • lower_bound / upper_bound：在已排序区间上二分，返回迭代器；对 vector 是 O(log n)，对 set 要用成员函数版本 s.lower_bound(x)（全局版是 O(n) 的）。
  • unique：只能去掉相邻重复，必须配合 sort 使用，且它不改变容器大小，要手动 erase。
  • next_permutation：枚举下一个排列，配合 sort 可遍历全排列。
  • nth_element：O(n) 求第 k 小，比 sort 快。
  • reverse / fill / count / max_element / accumulate / iota：一行搞定的小工具。
// 去重 + 离散化：把 1e9 的值域压到 1e5 的下标
vector<int> v(a, a + n);
sort(v.begin(), v.end());
v.erase(unique(v.begin(), v.end()), v.end());          // 经典三件套
int id = lower_bound(v.begin(), v.end(), x) - v.begin() + 1;  // 1-indexed

// set / map
set<int> s;
s.insert(3); s.erase(3);
auto it = s.lower_bound(2);      // 第一个 >= 2 的元素
if (it != s.end()) { /* ... */ }
map<string, int> mp;
mp["abc"] += 1;                  // 不存在时自动插入 0

// priority_queue：默认大根堆
priority_queue<int> big;                                   // 大根堆
priority_queue<int, vector<int>, greater<int>> small;      // 小根堆

自定义比较是高频坑点：sort 的 cmp(a, b) 表示「a 是否应排在 b 前面」；而 priority_queue 的 cmp(a, b) 表示「a 的优先级是否低于 b」，语义正好相反，写的时候容易搞混。用 lambda 时记得把类型传给 priority_queue 的模板参数（C++17 需要显式 decltype）。

复杂度与边界

  • vector::push_back 均摊 O(1)，扩容时按 1.5~2 倍增长，总拷贝量仍是 O(n)。
  • set/map 每次操作 O(log n)，常数比手写平衡树小，但比 vector 大很多。
  • priority_queue 建堆 O(n)，单次 push/pop O(log n)。
  • unordered_map 平均 O(1)，最坏 O(n)；n ≤ 5e5 且数据随机时可以放心用。
  • 关闭同步后 cin/cout 速度接近 scanf，但不要再混用 printf。

易错点

  • 在 vector 中间插入/删除：O(n) 搬移，循环里做就成了 O(n²)。
  • priority_queue 默认大根堆：求最小值要写 greater<int>（需 <functional>）或存相反数。
  • lower_bound 用在未排序区间：结果是未定义的，set 上要用成员函数而非全局版。
  • size() 返回无符号数：for (int i = 0; i < v.size() - 1; ++i) 在空 vector 上会下溢成天文数字。
  • 迭代器失效：vector 扩容后旧迭代器全失效；set::erase(it) 后 it 也失效，要用返回值 it = s.erase(it)。
  • unordered_map 被卡哈希：出题人故意构造同余数据即可退化成 O(n)，必要时换 map 或加随机扰动。
  • sort 比较器不满足严格弱序：相等时返回 true 会导致越界，务必返回 false。
  • endl 每次刷新缓冲：大量输出用 '\n'。

例题拆解

【模板】堆（Luogu P3378）

题意：维护一个初始为空的堆，支持三种操作：插入 x、输出最小值、删除最小值，操作数 n ≤ 1e6。

转化：这正是 priority_queue 的标准接口，只是默认是大根堆，而题目要小根堆。

做法：声明 priority_queue<int, vector<int>, greater<int>>，插入用 push，最小值是 top()，删除用 pop()。n 到 1e6 时必须关闭流同步，否则读入本身就会超时；也可以存 -x 用大根堆模拟。

复杂度：每次操作 O(log n)，总 O(n log n)，空间 O(n)。

统计数字（Luogu P1097）

题意：给出 n 个不超过 1.5e9 的正整数（n ≤ 2e5），按升序输出每个不同的数及其出现次数。

转化：要求「按值升序 + 去重计数」，排序后相同数字必然相邻，一次扫描就能分段统计。

做法：sort 后从左到右扫描，用 cnt 累计当前数字连续出现的次数，遇到不同值就输出上一段并重置；最后一段单独输出。用 map<int,int> 直接计数也行，但常数更大、内存更多。

复杂度：时间 O(n log n)（排序主导），空间 O(n)。

自测清单

  • 能按「是否需要有序」正确选择 set 与 unordered_set
  • 能默写 sort + unique + erase 去重三件套
  • 知道 set 上该用成员 lower_bound 而不是全局版
  • 能写出小根堆的完整声明，并说清自定义比较的语义方向
  • 能列出至少三个「STL 常数/失效」导致的 TLE 或 RE 场景
