网络流初步

在残量网络上不断找增广路，找不到时流量就是最大流。 · Dinic 一般 O(n²m)，单位容量网络接近 O(m√n)

一句话理解

把网络想成一套管道：每条边有个容量上限，水从源点流到汇点，问最多能流多少。做法朴素得惊人——只要能找到一条还没塞满的路径，就再塞一点进去，直到找不到为止。

核心思想

基本概念：每条边有容量 c，实际流量 f 满足 0 ≤ f ≤ c；除源点汇点外每点流入等于流出（流量守恒）。源点流出的净流量就是流值。

残量网络：把每条边剩下的空间 c - f 看成正向可用的边，再补一条容量为 f 的反向边——反向边的作用是「撤销」。所有增广都在残量网络上进行：一条从 s 到 t 的通路，路上的最小残量就是这次能增加的流量。

为什么贪心是对的：最大流最小割定理说最大流值等于最小割容量。当残量网络上找不到 s→t 通路时，把从 s 可达的点集记为 S，则所有从 S 流出的边都已满流，其容量和恰好等于当前流值，构成一个割——所以当前流已经最优。

Dinic 的两条优化：①分层（BFS）：先求距离标号 dep，DFS 只沿 dep[v] = dep[u] + 1 的边走，保证每次走最短路，避免来回复用一条边；②当前弧：用 cur[u] 记住扫到哪条出边，某条边榨干后本轮不再重扫，把重复扫废边的代价摊掉。

        s ──10──> a ──10──> t
        └── 5 ──> b ── 5 ──>┘
  第一次走 s-a-t 推 10 后，a-t 满了
  残量网络里出现 t->a 的反向边，允许把流量「退回」a 改走它路

模板与实现

const int N = 10005, M = 200005;
struct Edge { int to, nxt; long long cap; } e[M];
int head[N], tot = 1;                    // 从 1 开始，成对存边，i^1 是反向边
int dep[N], cur[N];

void addEdge(int u, int v, long long c) {
    e[++tot] = {v, head[u], c}, head[u] = tot;        // 正向边
    e[++tot] = {u, head[v], 0}, head[v] = tot;        // 反向边，初始容量 0
}

bool bfs(int s, int t) {                 // 分层：只保留 dep 递增的边
    memset(dep, -1, sizeof dep);
    queue<int> q;
    q.push(s), dep[s] = 0;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int i = head[u]; i; i = e[i].nxt) {
            int v = e[i].to;
            if (e[i].cap > 0 && dep[v] == -1) dep[v] = dep[u] + 1, q.push(v);
        }
    }
    return dep[t] != -1;                 // 汇点不可达 ⇒ 已无增广路
}

long long dfs(int u, int t, long long f) {
    if (u == t) return f;
    for (int& i = cur[u]; i; i = e[i].nxt) {          // 当前弧优化：i 是引用，会就地前进
        int v = e[i].to;
        if (e[i].cap > 0 && dep[v] == dep[u] + 1) {
            long long d = dfs(v, t, min(f, e[i].cap));
            if (d > 0) {
                e[i].cap -= d, e[i ^ 1].cap += d;     // 正向减、反向加
                return d;
            }
        }
    }
    return 0;
}

long long dinic(int s, int t) {
    long long flow = 0;
    while (bfs(s, t)) {
        memcpy(cur, head, sizeof head);               // 每轮 BFS 后重置当前弧
        while (long long f = dfs(s, t, LLONG_MAX)) flow += f;
    }
    return flow;
}

dfs 每次只推一条路是常见写法，外层 while 会反复调用直到推不动；也可以写成「把 f 用光」的多路版本，把同一层的剩余流量一次用完。

复杂度与边界

  • Dinic 一般图 O(V²E)，实际远快于此；单位容量网络（二分图匹配）有 O(E√V) 级别的界。
  • 空间 O(V + E)，但每条弧要存正反两条，边数组必须开 2m，tot 从 1 起才能用 i ^ 1 配对。
  • 流值可能超过 int（1e5 条边、容量 1e9 时到 1e14），容量与流量一律 long long。
  • 二分图匹配建模：源点连左部容量 1、左部连右部容量 1、右部连汇点容量 1，最大流即最大匹配。
  • 限制点权要靠「把一个点拆成入点与出点，中间连容量为限制的边」。

易错点

  • 边数组只开 m：正反边各一条，必须开 2m。
  • tot 从 0 开始：i ^ 1 就不再是反向边，配对全乱，必须从 1 起。
  • 忘了改反向边：只减正向容量不回加反向容量，就失去「撤销」能力，答案偏小。
  • BFS 没判 cap > 0：残量为 0 的边也当可走，会推出不存在的增广路。
  • 当前弧没重置：每轮 BFS 后 cur 必须拷回 head，否则漏解。
  • DFS 用 dep[v] == -1 判据：应沿层数恰好多 1 的边走，否则退化成普通 DFS。
  • 二分图中间边容量不设 1：一个点会被匹配多次，方案非法。

例题拆解

网络最大流（Luogu P3376）：求有向图的最大流。直接套 Dinic——BFS 分层、DFS 沿层找增广路并带当前弧优化，反复到汇点不可达为止，累计流量用 long long。

飞行员配对方案问题（Luogu P2756）：求二分图最大匹配并输出方案。建超级源点连所有外籍飞行员（容量 1）、所有英国飞行员连超级汇点（容量 1），可配对的两人之间连容量 1 的边；跑最大流，流量即匹配数。复原方案时枚举左部点的出边，cap 变成 0 说明这条边被用满，对应右部点就是配对。

自测清单

  • 能说清残量网络中反向边的作用，以及为什么需要它
  • 能复述「找不到增广路 ⇒ 当前流最优」的割论证
  • 知道 Dinic 分层与当前弧各自优化掉了什么
  • 能正确写出 i ^ 1 配对所需的建边方式
  • 会把一个二分图匹配问题建成最大流并复原方案
