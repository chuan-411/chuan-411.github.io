排序与贪心

排序把无序变成结构，贪心则在这份结构上每次只拿当下最好的。 · 排序 O(n log n)；贪心多为 O(n log n)（排序 + 一次扫描）或 O(n log n)（堆）

一句话理解

排序本身不解决问题，它只是把数据摆成「相邻即最优」的形状，让后面的贪心或二分有路可走。贪心的核心不是「选大的」直觉，而是能证明「换掉当前选择不会更差」。

核心思想

排序分两类：基于比较的排序（冒泡、选择、插入、归并、快排、堆排）下界是 O(n log n)；不基于比较的（计数、基数）能到 O(n + V)，代价是键值范围小且可分解。

  • 冒泡 / 选择 / 插入：O(n²)，n ≤ 5000 时能过，插入排序对近乎有序的数据接近 O(n)。
  • 归并排序：稳定，O(n log n)，顺手能统计逆序对。
  • 快速排序：平均 O(n log n)，常数最小，但朴素实现遇到全相同或已排序数据会退化成 O(n²)。
  • 堆排序：最坏 O(n log n)，不稳定。
  • 计数排序：O(n + V)，V 是值域，值域 1e6 以内很好用。

比赛里九成场合直接 std::sort，但记住两条：比较函数必须满足严格弱序（相等元素返回 false），否则是未定义行为，可能 RE 或死循环；需要保持相同键原有次序时用 stable_sort。

贪心的套路是：把问题拆成一串决策，每一步选当前看起来最优的那个，且选定后不回退。它成立的前提是最优子结构 + 贪心选择性质——存在一个最优解包含当前贪心选择。

证明常用交换论证：设最优解与贪心解在第一个不同位置分别选了 A 和 B，把最优解里的 A 换成 B，证明解不变差，于是存在与贪心一致的最优解。例：区间调度（最多选多少个不重叠区间）按右端点排序，右端点最小者一定可被选进某个最优解。

贪心最容易犯的错是「看起来对」。0-1 背包按性价比贪心就是经典反例：容量 10，物品 (价值 6, 重 6)、(价值 5, 重 5)、(价值 5, 重 5)，性价比贪心拿走第一件后装不下第二件，得 6，而最优是 5 + 5 = 10。所以写完贪心必须要么证明、要么对拍小数据。

模板与实现

// 1. 多关键字排序：比较器必须严格弱序（相等返回 false）
struct Node { int t, id; };

sort(a.begin(), a.end(), [](const Node& x, const Node& y) {
    if (x.t != y.t) return x.t < y.t;   // 第一关键字升序
    return x.id < y.id;                 // 第二关键字升序（保证结果唯一）
});

// 2. 区间调度：按右端点升序，能选就选
int maxIntervals(vector<pair<int,int>> seg) {   // {l, r}
    sort(seg.begin(), seg.end(),
         [](auto& x, auto& y) { return x.second < y.second; });
    int cnt = 0, last = INT_MIN;
    for (auto& [l, r] : seg)
        if (l >= last) { ++cnt; last = r; }     // 与上一段不重叠
    return cnt;
}

// 3. 合并果子：每次取最小的两堆 → 小根堆（哈夫曼）
long long mergeFruit(vector<int> a) {
    priority_queue<int, vector<int>, greater<int>> pq(a.begin(), a.end());
    long long cost = 0;
    while (pq.size() > 1) {
        int x = pq.top(); pq.pop();
        int y = pq.top(); pq.pop();
        cost += x + y;                          // 合并的代价是两堆之和
        pq.push(x + y);
    }
    return cost;
}

排序键的选择是贪心的第一道关卡：区间调度按右端点，接水问题按服务时间，任务调度按截止时间。选错键不会报错，只会 WA。

复杂度与边界

  • 排序 O(n log n)，空间 O(log n)~O(n)（归并需要 O(n) 辅助）。
  • 贪心一般是「排序 + 一次扫描」= O(n log n)；若每步都要取极值则用堆，仍是 O(n log n)。
  • 计数排序的 V 是值域：V ≤ 1e7 时还能用，再大就要换回比较排序。
  • 合并果子的总代价会超 int：n = 1e5、每堆 1e5 时总和可达 1e10，必须 long long。
  • 平均等待时间是小数，输出保留两位小数时用 double 并注意四舍五入。

易错点

  • 比较器写成 <=：违反严格弱序，std::sort 可能越界访问或死循环，务必让相等时返回 false。
  • 贪心没证明就交：先做交换论证，或者写个暴力对拍；0-1 背包、硬币找零（非规范币制）都是著名反例。
  • 排序键选错：区间调度按左端点排是错的，按右端点才能留出最多空间。
  • priority_queue 默认大根堆：要小根堆得写 greater<int>（需 <functional>）或存负数。
  • 排序后原下标丢失：需要输出原编号时把 id 一起存进结构体，不能只排值。
  • 相同键的次序：要求「时间相同则编号小的在前」时必须显式写第二关键字，或改用 stable_sort。
  • 整数除法丢精度：平均值用 double 算，别写 sum / n 之后再转。

例题拆解

排队接水（Luogu P1223）

题意：n 个人排队接水，第 i 个人需要 tᵢ 的时间，求一种排队顺序使所有人的平均等待时间最小，并输出该顺序与平均值。

转化：总等待时间 = Σ tᵢ ×（排在他后面的人数）。把短任务放前面，长任务的「后面人数」就少，总等待因此最小。

做法：按 tᵢ 升序排序，时间相同则按编号升序以保证输出字典序最小；排序后第 i 个位置的人贡献 t × (n - i)，累加后除以 n 保留两位小数。

复杂度：时间 O(n log n)（排序主导），空间 O(n)。

合并果子（Luogu P1090）

题意：n 堆果子，每次合并两堆，代价是两堆重量之和，求合并成一堆的最小总代价。

转化：这就是哈夫曼编码的构造过程——每次都让当前最小的两堆先合并，它们的重量才会在后续被重复计入最少的次数。

做法：把所有重量放进小根堆，循环取出最小的两个、相加计入答案、再把和压回堆，直到只剩一堆。用 long long 存答案。

复杂度：时间 O(n log n)（n - 1 次堆操作），空间 O(n)。

  • 能用交换论证说明区间调度为什么按右端点排序
  • 能举出一个贪心失效的反例并解释原因
  • 知道 priority_queue 怎么改成小根堆
