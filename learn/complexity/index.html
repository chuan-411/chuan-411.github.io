复杂度分析

不看机器看增长：先估量级，再决定这个想法能不能写。 · 常见为 O(1) ~ O(n log n)，据此反推可承受的数据范围

一句话理解

复杂度是给算法贴的价格标签：它不关心你在哪台机器上跑，只回答「输入翻一倍，时间涨多少」。会算复杂度，才能在 1 秒的限制里判断一个想法到底值不值得写。

核心思想

大 O 记号描述增长的量级：忽略常数因子与低阶项，只保留涨得最快的那一项。这样做的理由是，当 n 足够大时 3n² + 100n + 5000 的行为完全由 n² 决定，而不同机器、不同编译器的常数差异通常只有 2~5 倍，远小于量级之间的鸿沟。

常见量级由快到慢：O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)。OI 里一条实用经验是 C++ 每秒约能完成 1e8 次简单运算，于是 n ≤ 1e5 时 O(n log n) 安全，n ≤ 5000 时 O(n²) 勉强安全，n ≤ 20 才敢碰 2ⁿ 枚举。

分析时看「最内层语句被执行了多少次」，而不是数循环层数。两层循环不等于 O(n²)：for (i) for (j = i; j <= n; j += i) 的总次数是 n(1 + 1/2 + 1/3 + …) ≈ n ln n。递归算法先写递归式，归并排序 T(n) = 2T(n/2) + O(n) 解得 O(n log n)，二分 T(n) = T(n/2) + O(1) 解得 O(log n)。

n         log n     n log n        n²           2ⁿ
10        3         33             100          1024
1e3       10        1e4            1e6          天文数字
1e5       17        1.7e6          1e10         ——
1e6       20        2e7            1e12         ——

还要区分三种口径：最坏（题目默认考察的）、平均、均摊。vector::push_back 单次可能 O(n) 扩容，但均摊 O(1)；单调栈中每个元素最多进栈出栈各一次，整体 O(n)。空间同样要算：256MB 大约只装得下 6e7 个 int。

模板与实现

// 1. 用计数器验证「两层循环不一定 O(n^2)」
long long ops = 0;
for (int i = 1; i <= n; ++i)
    for (int j = i; j <= n; j += i) ++ops;   // 约 n·H_n ≈ n ln n

// 2. 归并排序的层数：共 log2 n 层，每层合并代价 O(n)
long long ops2 = 0;
for (long long len = 1; len < n; len <<= 1)  // len 翻倍 → log 层
    ops2 += n;                               // 每层扫一遍 → 总计 n log n

// 3. 二分：每轮区间减半，循环次数即 log2 n
int layers = 0;
for (long long r = n; r > 1; r = (r + 1) / 2) ++layers;

写代码时的取舍顺序是：先看数据范围猜预期复杂度，再选数据结构，最后才抠常数。范围小（n ≤ 100）时直接三重循环最省事，不必为了「优雅」去写树状数组。

复杂度与边界

  • 时间限制 1s 时给自己留 3~5 倍余量；多组数据要把单组代价乘上组数 T。
  • 常数会改变结论：取模、浮点除法、std::function 递归、map 每次 O(log n) 的常数都不小，理论上的 O(n log n) 也可能 TLE。
  • 空间边界：int f[1005][1005] 约 4MB，int f[10005][10005] 就是 400MB，直接 MLE。
  • 递归深度也是空间：链状图 DFS 深度可达 O(n)，n = 1e5 时容易栈溢出。

易错点

  • 把 1e8 当绝对安全线：带取模、浮点、STL 容器的操作慢 3~10 倍，1e8 次取模很可能已经超时。
  • 只数循环层数：循环变量步长不是 1 时（j += i、len <<= 1）必须用求和或等比级数算真实次数。
  • 混淆最坏与均摊：push_back、并查集路径压缩、单调栈的复杂度都要按均摊口径讲，单次最坏可能很贵。
  • log 的个数算错：底数是常数倍可以忽略，但几层 log 不能忽略，二维偏序是 O(n log² n)。
  • 空间开爆：不经计算就开大数组，二维表按 n × m 直接撑爆内存限制。
  • 递归层数当常数：写递归只算时间复杂度，忘了栈空间与栈溢出风险。

例题拆解

陶陶摘苹果（Luogu P1046）

题意：给出 10 个苹果离地高度，以及陶陶把手伸直能达到的高度，她还能踩 30 厘米高的板凳，问最多摘到几个苹果。

转化：能摘到的条件是「苹果高度 ≤ 伸手高度 + 30」，这是一个与顺序无关的计数问题。

做法：读入后逐个比较并累加，不需要排序也不需要任何数据结构。

复杂度：时间 O(n)，空间 O(1)。这里 n = 10，任何写法都能过，正说明「范围决定写法」——不要为小数据过度设计。

快速排序（Luogu P1177）

题意：把 n 个数从小到大排序，n ≤ 1e5。

转化：n = 1e5 时冒泡排序约 1e10 次比较，按每秒 1e8 次估算需要 100 秒，必然超时，所以必须用 O(n log n) 的算法。

做法：直接调用 std::sort（内省排序，平均与最坏都是 O(n log n)）；若手写快排，则随机化基准或三数取中，避免全相同、已有序的数据把划分退化成 O(n²)。

复杂度：时间 O(n log n)，空间 O(log n)（递归栈）。

自测清单

  • 能说出 n = 1e5、n = 5000、n = 20 分别对应哪档复杂度
  • 能用求和或等比级数算清一个非平凡循环的执行次数
  • 能写出归并排序与二分的递归式并解出结果
  • 能区分最坏、平均、均摊三种复杂度并各举一例
  • 会估算一个二维数组占多少内存
