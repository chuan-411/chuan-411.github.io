字典树与 AC 自动机

用公共前缀压成一棵树，再给每个结点挂一条失配指针。 · 建树 O(∑|s|)，匹配 O(|T| + 结点数)

一句话理解

字典树把字符串按公共前缀合并成一棵树，走到哪个结点就代表读到了哪个前缀；AC 自动机再给每个结点加一条失配指针，指向它最长的、仍是某模式串前缀的真后缀，于是多模式串匹配能像 KMP 一样不回头。

核心思想

字典树的结点表示「一个前缀」，边表示「追加一个字符」。插入和查询都沿边走，代价只与串长有关，与已经存了多少串无关。把字符集换成 {0,1} 就得到 01-Trie，常用来求「与 x 异或最大的数」：从高位贪心地走相反位。

AC 自动机 = Trie + fail 指针。fail[u] 的定义是：u 所代表串的最长真后缀中，能在 Trie 里找到的那个结点。它与 KMP 的 next 完全同源，只是从「一条链」推广到「一棵树」，因此必须按 BFS 层序求——孩子的 fail 由父亲的 fail 转移而来，DFS 会用到还没算好的值。

匹配阶段最容易写错。若每次失配都沿 fail 链暴力跳，aaaa…a 这类数据会把复杂度卡到 O(|T|·|S|)。正确做法是只记录文本串经过了哪些结点，再把计数沿 fail 树自底向上累加：一个模式串出现，当且仅当它的终止结点是被经过结点的 fail 祖先。这样每个字符只做 O(1) 次转移，最后统一 O(结点数) 汇总。

第二条优化是补边：建 fail 时顺手把空儿子 ch[u][c] 指向 ch[fail[u]][c]，匹配时就不必再写跳 fail 的循环。

        root
        /  \
       a    b
       |    |
       b    c        fail： ab --失配--> b
       |

模板与实现

字典树

const int MAXN = 300005;                 // 结点数按「所有串长之和」开
int ch[MAXN][26], pas[MAXN], tot = 1;    // tot = 1：1 号结点是根

void insert(const string& s) {
    int u = 1;
    for (char c : s) {
        int v = c - 'a';
        if (!ch[u][v]) ch[u][v] = ++tot; // 此前没有这个前缀才新建结点
        u = ch[u][v];
        ++pas[u];                        // 经过该前缀的串数 +1
    }
}

int query(const string& s) {             // 有多少个串以 s 为前缀
    int u = 1;
    for (char c : s) {
        int v = c - 'a';
        if (!ch[u][v]) return 0;
        u = ch[u][v];
    }
    return pas[u];
}

AC 自动机

const int MAXN = 1000005;
int ch[MAXN][26], fail[MAXN], occ[MAXN], tot = 1;
bool isEnd[MAXN];
vector<int> ord;                         // BFS 序，用于逆序累加

void insert(const string& s) {
    int u = 1;
    for (char c : s) {
        int v = c - 'a';
        if (!ch[u][v]) ch[u][v] = ++tot;
        u = ch[u][v];
    }
    isEnd[u] = true;                     // 重复出现的同一串落在同一结点，天然去重
}

void build() {
    queue<int> q;
    for (int c = 0; c < 26; ++c) {
        int v = ch[1][c];
        if (v) fail[v] = 1, q.push(v);   // 根的儿子失配后回到根
        else ch[1][c] = 1;               // 根的空边指向根
    }
    while (!q.empty()) {
        int u = q.front(); q.pop();
        ord.push_back(u);                // 记录 BFS 序
        for (int c = 0; c < 26; ++c) {
            int v = ch[u][c];
            if (v) fail[v] = ch[fail[u]][c], q.push(v);   // 孩子的 fail = 父亲 fail 的同名儿子
            else ch[u][c] = ch[fail[u]][c];               // 补边，失配 O(1) 转移
        }
    }
}

int query(const string& t) {             // 有多少个不同的模式串在 t 中出现
    int u = 1;
    for (char c : t) { u = ch[u][c - 'a']; ++occ[u]; }
    for (int i = (int)ord.size() - 1; i >= 0; --i) {
        int u = ord[i];
        occ[fail[u]] += occ[u];          // 沿 fail 树自底向上累加
    }
    int res = 0;
    for (int u = 2; u <= tot; ++u)
        if (isEnd[u] && occ[u]) ++res;
    return res;
}

复杂度与边界

  • 建 Trie O(∑|s|)；建自动机 O(结点数 × 字符集)；匹配 O(|T| + 结点数)。
  • 空间是主要瓶颈：int ch[MAXN][26] 每结点约 100 B，1e6 结点就要 100 MB 以上，此时改用按需 new，或把字符集压成 0/1。
  • 多组数据必须清空 tot、fail、occ、isEnd 与 ch[1..tot]，漏清一定 WA。

易错点

  • 用 DFS 求 fail：fail 依赖层数更浅的结点，只能按 BFS 层序求。
  • 匹配时暴力跳 fail 统计：aaaa…a 会退化到 O(|T|·|S|)，必须改成 fail 树上逆序累加。
  • 根的儿子忘了入队：根的 26 个儿子 fail 都指向根且都要入队，否则第二层以下的 fail 全是 0。
  • 重复模式串重复计数：同一串多次插入落在同一结点，按插入次数统计就会算重，用 isEnd 去重。
  • 统计从根开始：根固定为 1，统计要从 2 起，否则空串也会被算作答案。
  • 多组数据没清 ch：只把 tot 置 1 而不清残留的边，上一组会被当成本组的。

例题拆解

字典树（Luogu P8306）：问每个询问串是多少个模式串的前缀。前缀关系就是 Trie 上的祖先关系：插入时给路径上每个结点 ++pas，询问时沿边走，走不通返回 0，走完返回 pas[u]，复杂度 O(∑|s| + ∑|t|)。

AC 自动机（简单版）（Luogu P3808）：求有多少个不同模式串在文本串中出现。模式串出现等价于它的终止结点是被经过结点的 fail 祖先；于是建 Trie 与 fail（BFS + 补边），文本串跑一遍给经过结点计数，再按 BFS 逆序把 occ 累加到 fail 父亲，最后数 isEnd && occ > 0 的结点。

自测清单

  • 能手写 Trie 的插入与「前缀个数」查询
  • 能说清 fail 指针与 KMP next 的对应关系
  • 知道为什么 fail 必须按 BFS 层序求
  • 能解释「逆序累加」如何避免暴力跳 fail
  • 会估算 Trie 的内存，并在结点过多时换存储方式
