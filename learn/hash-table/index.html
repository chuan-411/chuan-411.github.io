哈希表与字符串哈希

用一次取模把大值域压进小数组，再用冲突处理把期望 O(1) 稳住。 · 期望 O(1) 插入/查询；字符串哈希预处理 O(n)、子串比较 O(1)

一句话理解

哈希是把「值本身」换成「它在一个小数组里的门牌号」：门牌号算得快、占得少，代价是不同值可能撞到同一扇门，所以要额外定一套处理冲突的规矩。

核心思想

要区分两个东西。哈希表维护一个动态集合，支持插入、查找、删除，冲突用拉链法（每个桶挂一条链）或开放寻址法（线性探测，桶数开到元素数的 2~3 倍）解决。字符串哈希把字符串看成 base 进制数，配合前缀哈希就能 O(1) 取出任意子串的指纹，用来判重、判相等、求最长公共前缀。

哈希是概率算法：它假设哈希函数把关键字均匀打散，于是单次操作期望 O(1)。风险来自生日悖论——桶数 m、元素 n 时，冲突概率约为 n²/(2m)，所以 m 必须开到 n 的数倍，不能「刚好等于 n」。字符串哈希的风险则由模数位数决定：单模 1e9 级别在十万个串时已有实际碰撞可能，双模或 64 位自然溢出更稳，但自然溢出等价于模 2^64，可被构造数据卡掉。

与平衡树相比，哈希表期望 O(1) 但最坏 O(n)，且无序；需要前驱后继时必须换 set/map。与 Trie 相比，字符串哈希擅长整体比较与子串询问，不擅长前缀枚举。

模板与实现

1. 拉链法哈希表（值域大、元素少时最常用）

struct HashTable {
    static const int M = 100003;         // 质数，约为元素数的 2~3 倍
    vector<int> head, nxt, val;          // 链式前向星存每个桶
    HashTable() : head(M, -1) {}
    int h(int x) { return ((x % M) + M) % M; }   // 负数取模要修正
    bool find(int x) {
        for (int i = head[h(x)]; ~i; i = nxt[i])
            if (val[i] == x) return true;
        return false;
    }
    void insert(int x) {
        if (find(x)) return;
        int k = h(x);
        val.push_back(x);
        nxt.push_back(head[k]);
        head[k] = (int)val.size() - 1;
    }
};

2. 字符串哈希（前缀哈希 + 子串查询）

typedef unsigned long long ull;
const int N = 1e5 + 5, B = 131;
ull pw[N], h[N];                  // h[i] 是 s[1..i] 的哈希
void init(const string& s) {      // 约定 s 下标从 1 开始
    int n = (int)s.size() - 1;
    pw[0] = 1, h[0] = 0;
    for (int i = 1; i <= n; ++i) {
        pw[i] = pw[i - 1] * B;
        h[i] = h[i - 1] * B + (ull)s[i];   // 字符值从 1 起，避免前导零
    }
}
ull sub(int l, int r) {           // s[l..r] 的哈希
    return h[r] - h[l - 1] * pw[r - l + 1];
}

需要更强的保证时，把 ull 换成两对 (base, mod) 同时算，比较二元组即可。

复杂度与边界

  • 哈希表期望 O(1)，最坏 O(n)；空间 O(n + M)。
  • 字符串哈希预处理 O(n)，此后任意两段比较 O(1)，空间 O(n)。
  • 元素规模 1e5 内手写拉链表完全够用；1e6 以上要注意多测清空的代价。
  • 桶数取质数且不小于 2n；开放寻址的装载因子控制在 0.5 以下，否则探测链变长。
  • 需要按 key 排序、求前驱后继时不要用哈希表，直接上平衡树或排序后二分。

易错点

  • 负数取模：C++ 的 % 结果符号跟着被除数，h(x) 必须写成 ((x % M) + M) % M，否则下标为负直接 RE。
  • 桶数取成合数或不大于元素数：装载因子接近 1 时拉链退化成一条长链，期望 O(1) 变成 O(n)。
  • 多测忘记清空：全局 head 和计数器不重置会串数据，而每次 memset 整个大数组又容易 TLE。
  • 字符值用 0 起："a" 与 "aa" 会得到同一个哈希，必须让字符值从 1 开始。
  • 下标越界：sub(l, r) 里 h[l-1] 在 l = 1 时要用 h[0]，前缀哈希必须从 0 号位初始化。
  • 只判存在性：像点名题还要记录「是否已被点过」，信息不足会漏状态。

例题拆解

【模板】字符串哈希（Luogu P3370）：给 n 个字符串，求不同字符串的个数。 转化：判重问题，只需给每个串算一个指纹，再看指纹是否重复出现。 做法：对每个串做多项式哈希（双模或 ull），把哈希值排序后统计相邻不同的个数，也可直接塞进哈希表；怕碰撞就存 (h1, h2) 二元组。 复杂度：O(总长 + n log n)，排序主导。

于是他错误的点名开始了（Luogu P2580）：给 n 个名字，随后 m 次点名，分别输出 OK（第一次点到）、REPEAT（重复点到）、WRONG（名单里没有）。 转化：本质是「名字是否存在」加上「是否已被点过」两个状态。 做法：把名字哈希进表，每个槽位额外存一个访问标记；查询时先判存在再判标记。名字总长很大时用字符串哈希当 key 比直接存 string 更省。 复杂度：O(总长 + m)。

自测清单

  • 能说清拉链法与开放寻址法各自怎么删除元素
  • 能解释桶数为什么要取质数且大于元素数
  • 能默写双模字符串哈希并正确取出子串
  • 知道 ull 自然溢出为什么可能被构造数据卡掉
  • 能判断一道题该用哈希表还是平衡树
