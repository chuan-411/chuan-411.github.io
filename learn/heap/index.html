堆与优先队列

只维护「最值」的完全二叉树：把找最值从 O(n) 压到 O(log n)。 · 插入与删除堆顶 O(log n)，取最值 O(1)，自底向上建堆 O(n)

一句话理解

堆是一棵「父亲永远不比孩子差」的完全二叉树，你只能立刻知道谁在最上面，其余元素之间没有顺序保证。它像一个只保证「最小的人在队首」的队列。

核心思想

堆只维护偏序：小根堆满足 h[fa] ≤ h[son]，于是堆顶就是全局最小值；但左右孩子之间、不同子树之间没有任何约束，所以堆不是有序结构，不能二分查找。

它用数组存完全二叉树：下标 i 的孩子是 2i 与 2i+1，父亲是 i/2，不需要指针，也没有内存碎片。两个基本动作撑起所有操作：上浮（新元素放在末尾，不断和父亲比较交换）与下沉（删除堆顶时把末尾元素搬到根，再和较小的孩子交换）。所有操作都只沿一条根到叶的路径走，长度是 log n。

自底向上建堆只需 O(n)：从 n/2 倒着对每个节点下沉，高度为 h 的节点有 n/2^h 个，加权求和收敛到 O(n)。逐个插入建堆则是 O(n log n)，数据量大时差别明显。

堆的典型用途是「每次只需要当前最优」的贪心：合并果子、Huffman 编码、Dijkstra 取最近点、多路归并、按时间推进的模拟调度。需要第 k 大/小时，用对顶堆——一个大根堆存较小的一半、一个小根堆存较大的一半，两堆大小关系固定，则某一侧的堆顶就是答案。

模板与实现

1. 手写小根堆（需要可删、可改键时用）

const int N = 1e6 + 5;
int h[N], sz;
void up(int i) {
    while (i > 1 && h[i] < h[i >> 1])
        swap(h[i], h[i >> 1]), i >>= 1;
}
void down(int i) {
    while ((i << 1) <= sz) {
        int j = i << 1;
        if (j < sz && h[j + 1] < h[j]) ++j;   // 选较小的孩子
        if (h[j] >= h[i]) break;
        swap(h[i], h[j]);
        i = j;
    }
}
void push(int x) { h[++sz] = x; up(sz); }
int  top()       { return h[1]; }
void pop()       { h[1] = h[sz--]; if (sz) down(1); }
void build(int n) { sz = n; for (int i = n >> 1; i; --i) down(i); }  // O(n)

2. priority_queue 与对顶堆

priority_queue<int> big;                                 // 默认大根堆
priority_queue<int, vector<int>, greater<int>> small;    // 小根堆

priority_queue<int> L;                                   // 前 k 小，堆顶是第 k 小
priority_queue<int, vector<int>, greater<int>> R;        // 剩余部分
void insert(int x) {
    if (L.empty() || x <= L.top()) L.push(x);
    else R.push(x);
}
void rebalance(int k) {                                  // 让 L 的大小恰好为 k
    while ((int)L.size() > k) { R.push(L.top()); L.pop(); }
    while ((int)L.size() < k) { L.push(R.top()); R.pop(); }
}

小根堆要存 int 最小值时，用 greater 或存相反数；若用存负数的写法，注意 -INT_MIN 溢出。

复杂度与边界

  • 插入、删除堆顶 O(log n)；取堆顶 O(1)；建堆 O(n)；空间 O(n)。
  • 需要「删除任意元素 / 修改键值」时，堆要配合位置数组，或者改用平衡树。
  • 需要区间最值、区间加时不能用堆，改用线段树。
  • 堆的常数比线段树小很多，1e6 次操作优先考虑堆。
  • 对顶堆额外代价是两倍空间，且必须保证两堆大小关系始终成立。

易错点

  • 默认是大根堆：priority_queue<int> 的 top() 是最大值，求最小值务必写 greater。
  • 存负数时溢出：-x 在 x = INT_MIN 时不可表示，改存 long long 或直接用 greater。
  • 忘记判空：空堆调用 top() 是未定义行为，pop() 前要保证 sz > 0。
  • 逐个插入建堆：n 次 push 是 O(n log n)，能用 build 就别偷懒。
  • 对顶堆顺序错：先插入再平衡，且平衡前要保证目标大小不超过元素总数。
  • 多测不清空：手写堆的 sz 与数组必须一起重置，否则残留元素会污染下一次询问。

例题拆解

合并果子（Luogu P1090）：每堆果子有重量，每次合并两堆、代价为两堆之和，求合并成一堆的最小总代价。 转化：每次都应该合并当前最小的两堆，这是标准的贪心，等价于构造 Huffman 树。 做法：小根堆维护所有堆的重量，反复弹出两个最小值、把和压回堆并累加代价，直到只剩一堆。用堆而不是每次排序，复杂度从 O(n² log n) 降到 O(n log n)。 复杂度：O(n log n)，空间 O(n)。

黑匣子（Luogu P1801）：给定序列和递增的 u[i]，在插入前 u[i] 个数后，输出当前第 i 小的数。 转化：动态插入，查询的排名单调递增，适合对顶堆。 做法：大根堆 L 保存前 k 小的元素，小根堆 R 保存其余；每次插入后令 k 自增并调用 rebalance(k)，此时 L.top() 就是第 k 小。也可用线段树/树状数组维护值域，但代码更长。 复杂度：每次插入与调整均摊 O(log n)，总计 O((n + m) log n)。

自测清单

  • 能手写 up 与 down 并说清各自的终止条件
  • 能证明自底向上建堆是 O(n)
  • 知道什么时候该用小根堆存相反数
  • 能写出对顶堆并保证两堆大小关系
  • 能判断一道题该用堆还是线段树
