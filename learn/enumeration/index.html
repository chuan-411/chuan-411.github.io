枚举、模拟与构造

想不清就穷举：先保证不重不漏，再想办法少枚举一点。 · O(枚举量)，剪枝与倒序枚举常把 n² 压成 n

一句话理解

枚举就是「把所有可能性挨个试一遍」，模拟就是「照着题目写的流程一步步走」。它们不需要巧思，但极考验你有没有把边界想全——写对了是送分题，写漏一处就变成调半天的玄学。

核心思想

枚举的第一原则是不重不漏：把候选集合切成一堆互不相交的子集，每个子集用一个循环或一次递归走完。写之前先回答三个问题——枚举什么、范围多大、怎么验证一个候选。

第二原则是能少枚举就少枚举。常见手段有：

  • 换枚举对象：求「覆盖某点的最后一张地毯」，与其枚举所有地毯去覆盖点，不如倒序枚举地毯、第一个覆盖该点的就是答案，O(n) 解决。
  • 用约束缩小范围：枚举因数只需到 i * i <= n，因为因数成对出现。
  • 剪枝：当前代价已经超过已知最优就返回；前缀和已不满足条件就 break。

模拟的关键是抽象状态：把题目里的人、棋盘、队列、时间映射成变量与数组，再写一个清晰的循环。方向移动一律用方向数组，比手写四段 if 更不容易错。模拟题最大的风险不是算法，而是题意细节（谁先动、越界算不算、多组数据要不要清空）。

构造题通常是「先看小数据找规律，再从特殊推到一般」：n 为奇数怎么摆、n 为偶数怎么摆、边界 n = 1 怎么处理。构造的验证方式是自证——写完后自己检查每个约束是否满足。

方向数组（8 邻域）：
  (-1,-1) (-1,0) (-1,1)
  ( 0,-1)   x    ( 0,1)
  ( 1,-1) ( 1,0) ( 1,1)
访问前先判 0 <= nx < n && 0 <= ny < m

模板与实现

// 1. 倒序枚举：找「最后覆盖某点」的对象
int solve(int n, vector<array<int,4>>& r, int x, int y) {
    for (int i = n - 1; i >= 0; --i) {           // 从最后一张往前找
        int a = r[i][0], b = r[i][1], g = r[i][2], k = r[i][3];
        if (a <= x && x <= a + g && b <= y && y <= b + k) return i + 1;
    }
    return -1;                                    // 没有任何一张覆盖
}

// 2. 网格模拟：方向数组 + 边界判断
const int dx[8] = {-1,-1,-1, 0, 0, 1, 1, 1};
const int dy[8] = {-1, 0, 1,-1, 1,-1, 0, 1};

void minesweeper(int n, int m, vector<string>& g) {
    vector<string> ans(n, string(m, '0'));
    for (int i = 0; i < n; ++i)
        for (int j = 0; j < m; ++j) {
            if (g[i][j] == '*') { ans[i][j] = '*'; continue; }
            int cnt = 0;
            for (int d = 0; d < 8; ++d) {
                int x = i + dx[d], y = j + dy[d];
                if (x < 0 || x >= n || y < 0 || y >= m) continue;  // 先判界再访问
                if (g[x][y] == '*') ++cnt;
            }
            ans[i][j] = char('0' + cnt);
        }
}

枚举的写法优先级：范围小（n ≤ 100）就用最朴素的多重循环；范围到 1e4 时考虑倒序、排序后双指针或前缀和；范围到 1e5 时基本要换算法。

复杂度与边界

  • 枚举的总代价是「候选个数 × 单次验证代价」，两项都要算，别只盯着循环层数。
  • 数据范围是题目的暗示：n ≤ 20 想 2ⁿ 枚举，n ≤ 1e4 允许 O(n²)，n ≤ 1e5 只留给 O(n log n)。
  • 模拟题要按最坏情况估：网格 n·m ≤ 1e6 时 O(nm) 没问题，但每次操作都扫一遍全图就可能到 1e10。
  • 多组数据的时间要乘 T，空间要记得每组清空。

易错点

  • 枚举范围差一：起点 0 还是 1、闭区间还是半开区间，先在纸上标清楚再写循环。
  • 重复计数：无序对要固定 i < j；排列枚举要用 used 数组；同一状态被两条路径枚举到会翻倍。
  • 该倒序却正序：求「最后一次覆盖 / 最后被修改」时必须从后往前，正序拿到的是第一次。
  • 模拟越界：访问 g[x][y] 前先判 0 <= x < n，方向数组最容易踩这个坑。
  • 多组数据没清空：全局数组、计数器、visited 标记必须每组重置，否则第二组直接错。
  • 输出格式不符：行末空格、最后一行换行、大小写、-1 的写法，都会被逐字符比对。
  • 循环变量被覆盖：内层循环复用了外层变量名，编译能过但逻辑全错。

例题拆解

铺地毯（Luogu P1003）

题意：依次铺 n 张矩形地毯，后铺的盖住先铺的；询问某个点最上面那张地毯的编号，没有被覆盖输出 -1。

转化：「最上面」等价于「编号最大的、覆盖该点的地毯」，而地毯是按编号顺序铺的，所以从 n 倒着找，第一个覆盖该点的就是答案。

做法：把每张地毯存成左下角与长宽，倒序枚举并做矩形包含判断，命中即输出编号并结束。

复杂度：时间 O(n)，空间 O(n)；正序枚举再取最大值也是 O(n)，但倒序可以提前退出，实际更快。

扫雷游戏（Luogu P2670）

题意：给出 n × m 的雷区，* 表示地雷，要求把每个非雷格子换成它周围八个方向的地雷数。

转化：每个格子的答案只依赖它自己的 3 × 3 邻域，格子之间互不影响，所以可以独立计算，不需要搜索或递推。

做法：对每个格子枚举八个方向，越界的直接跳过，统计邻域内 * 的个数；雷格本身保持 * 不变。

复杂度：时间 O(8nm) = O(nm)，空间 O(nm)；n, m ≤ 100 时约 8e4 次判断。

自测清单

  • 能在动手前说清「枚举什么、范围多大、怎么验证」
  • 会用倒序枚举把「最后一次」类问题压到 O(n)
  • 能默写八个方向的方向数组并正确判界
  • 知道无序对枚举为什么要固定 i < j
  • 多组数据时能列出所有需要清空的变量
